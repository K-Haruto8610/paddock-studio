# Paddock Studio

JRA平地GⅠの展開を、馬柱を学習したLightGBMと3Dの馬で表示するWeb試作。
回収率・的中率は目的にも評価指標にも含めない。

## 現在の実装
- 指定フォルダのmykeibadbを読み取り専用で利用。DBの更新・変更は行わない。
- 各角の正規化通過順位4モデルと上がり3Fモデル。
- 完全な出走頭数と有効な馬名・レース名を持つデータを選別。
- 2025年8月までで学習、9〜12月で時系列検証。推論用は2025年末までで再学習。
- 2026年の正常なGⅠ17レースを掲載（2026-11-18のDB取り込み直しで菊花賞・秋華賞・スプリンターズSが加わった）。対象レース結果は特徴量や学習に入れない。
- 過去走は対象日より前の最大5走。オッズ、人気、払戻をモデルに渡さない。
- 毛色・馬番・馬名・ブリンカー（メンコ。色は馬名から決まる馬ごとの色）を表示。馬具不明は未取得として扱う。
- 3D再生、シーク、速度変更、馬群追尾カメラ（ドラッグで手動、「馬群を追尾」で復帰）、馬柱の閲覧。
- コースの描画：芝（刈り目）・ダート（ハロー跡）・地面は手続き生成のテクスチャ、走路の縁は法面で地面につなぐ。内外ラチは支柱が外側から腕を出す形、200mごとのハロン棒、発馬機（仕切り・枠・車輪）（`app/scenery.ts`）。ゴール板はGⅠ当日風の装飾（レース名と日付の入った蹄鉄型アーチ、鏡付きの決勝標、競馬場名の標識、内ラチ沿いの花壇と横断幕）で、配色はレースIDから決まるレースごとの色。実在の装飾の再現ではない独自デザイン（`app/goalBoard.ts`）。
- シークバーの背景にJRA公式の高低断面図を表示し、レース全体のどこを走っているかを示す。バーの向きはスタンドから見た馬の進む向きに合わせ、左回りは左→右、右回りは右→左（スタートが右端、ゴールが左端）。
- 実績再生とモデル予想を切替。実績は別ファイルreplays.jsonから読み込み、予測特徴量には渡さない。
- 実績再生は各角通過順位・入線順位に一致するよう補間。未観測コーナーを省略し、直線も入線順位まで変化する。
- 手動エディット：予想をもとに序盤（スタートから200m）・中盤（レースの中間）・4角・最終直線（直線の中間）の4地点で、馬をドラッグ（前後＝進行方向、左右＝内外）またはボタンで動かす。動かした差は次にその馬を編集するまで以降の地点とゴールに引き継ぐ。編集はブラウザーに保存（`app/manualEdit.ts`）。
- 予想の録画：モデル予想・手動エディットで「録画」を押すと、スタートからゴールまで再生しながらレース画面・シークバー（高低断面図・地点・現在位置）・隊列を1本のMP4（1280×990）に録画して保存する（`app/recorder.ts`）。一時停止・シーク・レース切替で録画を終えて保存。MediaRecorderのMP4出力を使うため、Chrome・Edge（最新版）またはSafariが必要（Firefoxは非対応）。録画中にタブを裏に回すと描画が止まり、その間の映像は止まる。

## 実行
```
npm run dev
python scripts/validate_g1_master.py     # GⅠマスター(data/g1_races.json)とDBの照合
python scripts/fetch_entries.py          # 直近2週間のGⅠ出馬表を data/entries/ に保存（--dry-run, --refresh）
python scripts/check_entries.py          # 取消・馬具変更などの差分処理の自己検査
python scripts/build_forecasts.py        # 過去GⅠ + 出馬表確定済みの発走前GⅠを出力
python scripts/export_replays.py         # DBの実績 + data/results/<RACE_CODE>.json（DBの行が使えないレースの手入力結果）
python scripts/pace_model.py             # 展開予想モデル（forecasts.json の後に実行）→ public/data/pace_forecasts.json
node scripts/check_pace.mjs              # 展開予想の取り込み・再生の検査
node scripts/check_passing.mjs           # 追い越し中に内外が入れ替わらないことの検査
python scripts/digitize_jra_courses.py   # JRA図面の読取（references/jra → app/courseData.ts, public/courses）
npx tsc --noEmit
node scripts/check_replay.mjs
```
Pythonはpymysql / pandas / numpy / lightgbm / python-dotenvが必要。
KEIBA_SOURCE環境変数で既存mykeibaのパスを指定できる。認証情報は既存設定をメモリー内で参照し、生成物には含めない。
モデルはmodels/、Web向け予想データはpublic/data/forecasts.json。

## 展開予想モデルと取り込み形式
`scripts/pace_model.py` は各角の **途中順位**・**前後**（先頭からの馬身差）・**左右**（内外）と **上がり3F** を予想する（LightGBM、時系列検証は2025年9〜12月、推論用は2025年末まで再学習。モデルは `models/pace/`）。
- 正解ラベル：順位は `CORNERn_JUNI`。馬身差と内外は `race_shosai.KAKU_TSUKA_JUNI1〜4`（JRA通過順表記）を復元。`( )`＝1馬身未満の併走で内側の馬から順、`,`＝1〜2馬身、`-`＝2〜5馬身、`=`＝5馬身以上、記号なし＝1馬身未満。各記号の幅の中央値（0.6/1.5/3.5/6.5馬身）で近似。
  `CORNERk` の値（実際の角番号）で角を対応づける（1600mの東京なら3・4角のみ）。
- 学習用の内外は「併走群の内からの位置（0=最内または単独）」。予想出力では前の角からの進路を引き継ぐため、単独の馬も外側の位置を保つ。いずれも実測のラチ距離ではない。
- 馬身差は「順位モデルの並び × 馬ごとの差モデル（L1）の形と等間隔の平均 × レース単位の隊列長モデル（80%位置の馬の差）」で再構成し、順位と矛盾しないようにした。
- ゴールは最終角の馬身差＋上がり3F差（1秒＝5馬身）による推定で、着順モデルではない。
- **ポジション争い（レース内の相互作用）**：馬ごとのモデルは「その馬が行きたい位置」を出し、その後に角ごとの割り当てを行う。押し出しの強さ＝希望位置と前の角の位置の混合（alpha）。近い馬（delta以内）は併走になり、通常は4頭、先行型（早い位置取りの上位front割）は5頭まで。前の角より希望順位を上げる馬は、追い抜く相手の外へ進み、この頭数制限を受けない。4角以降も頭数制限を解除する。左右位置は前の角から引き継ぎ、列ごとに内側へリセットしない。通常時に列が埋まって進めない馬は控えて hold だけ下がる。後ろから押してくる馬に抜かれるので位置を失い、次の角も前の位置を引き継ぐ。
- **仕掛け遅れ**：上がり3Fモデルは最終角の渋滞（外に並ぶ頭数・1馬身未満の前の壁）を特徴量に学習する。渋滞は遅くする方向にしか効かない単調制約付き。予想時はポジション争いで決まった隊列の渋滞を入れ、前が開いた場合との差を `kickDelay`（秒）として出す。
  根拠：2020〜2025年の位置を揃えた比較では、外に1頭いると上がりが約+0.11秒、1馬身未満の前の壁で約+0.17秒、包まれた馬は合計で約0.1〜0.3秒遅い。
- **前半のペース**：`race_shosai.ZENHAN_3F`（先頭の前半3F）をコースの標準（場・トラック・距離の中央値、2025年5月までで算出）と比べた秒差を、出走馬の先行型の頭数・過去に逃げた割合・その馬たちが走ったレースの前半の速さ・馬場状態から予想する（`pace`）。検証（9〜12月）：相関0.43、誤差0.71秒（定数予想0.78秒）、H/M/S 3区分の的中42%。GⅠは全クラス基準より平均0.87秒速いので、画面のラベルは過去GⅠ20レースの予想値の3等分で判定する。
  予想ペースは隊列の長さモデルに入れる（学習も予想値で行う。馬身差の誤差 1角3.92→3.77、4角2.42→2.37）。上がりには馬場状態（`going`）を入れる（0.950→0.931秒）。予想ペースを上がりに入れても検証では改善せず（レース内の上がり順位の相関は約0.29のまま）、入れていない。天皇賞（秋）2026ではハイペース予想（実際も標準より1.6秒速い）だったが、先行馬の失速（上がり36〜37秒）は再現できていない。
- **脚の消耗（2026-11-13）**：上がり3Fモデルに「速いペースで前にいた量」（`max(0, −前半ペース差) × (1 − 最初の角の正規化順位)`）と「普段より前で運んだ量」（二の足・かかりの代理、`max(0, 普段の序盤位置 − 最初の角の位置)`）を加えた（遅くする方向のみの単調制約）。学習時は実際のレースの値、予想時は予想ペースとポジション争いの1角位置を入れ、前が開いた場合の上がりとの差を `paceCost`（秒）として出す。
  検証（9〜12月、同じDB）：上がり誤差 0.915→0.902秒、着順推定の順位相関 0.173→0.177。重賞で予想ペースが速いレースの先行馬は残差ほぼ0（偏りなし）。天皇賞（秋）2026の着順相関 0.19→0.58（このレースは導入の動機なので独立した検証ではない）。
  馬ごとの坂適性・内外の分解（2026-11-13検証、不採用）：坂適性＝上がりのレース内偏差の「ゴール前に坂がある場（東京・中山・中京・阪神）」平均−「平坦な場」平均（縮小推定）。過去の値と次走の偏差の相関は約0.01で、持続する特性として取り出せなかった（1頭あたり両方の走数が少なく、上がり3Fは坂の区間だけの速さではない）。内外は「位置取りの不利（外を回った量）」と「馬場の傾向（同じ場・芝ダ・内柵の前9日の、4角の内外と4角→入線の順位変化の傾き）」に分けた。馬場の傾向が次のレースにも続く相関は0.07と弱く、どちらも上がりモデルに入れると誤差・着順相関とも悪化か横ばい。
  馬場の傾向は一般戦を含む全レース（1日約12レース）から推定し直し、名前付きレースで学習するモデルに入れても、2期間（2025年9〜12月／2026年1〜6月）で上がり誤差 +0.022秒／±0、着順相関 +0.004／−0.001と改善せず不採用。外を回った量も上がり順位相関が +0.030／−0.006 と期間で向きが逆で不採用。
  名前のない一般戦も学習に入れる（行数約3.7倍）と、名前付きレースの検証はむしろ悪化した（着順相関0.205→0.192）ため、名前付きレースのみのまま。
  採用しなかったもの：道中・4角手前で位置を上げた量（早仕掛け・まくり）はデータ上むしろ上がりが速い方向（強い馬ほど動ける交絡）で、消耗として取り出せなかった。遅いペースで前に行った量（かかりの典型）も効果ほぼ0。外を回った量は+0.06秒程度で見送り。坂は場・コースの特徴量で平均的な影響は吸収済みで、馬ごとの坂適性・坂での仕掛け位置は未実装。
- **道中の位置変化**：最初の角からの累積移動量（正規化順位の差）を2〜4角ごとに直接学習する（`move2〜4`。特徴量は過去5走の移動の平均・最大の上げ幅/下げ幅・出走馬中の「動く馬」の割合・角の数など）。2角以降は「最初の角の位置＋k×予想移動量（出走馬内で中心化）」と希望位置をbetaで混ぜてから、ポジション争いを行う。kとbetaは2025年6〜8月で「順位誤差の悪化が0.2%以内」の範囲で移動の相関が最大の値（beta=0.7, k=3）。
  以前は前の角の位置に強く引き戻していたため、1角→最終角の予想移動はほぼ0（実際の移動との相関 −0.002）だった。検証（9〜12月）：相関 0.144（過去5走の移動平均だけなら0.119）、全体の4分の1以上上げた馬の方向的中 10%→40%、下げた馬 7%→47%。代わりに順位誤差（全角平均）は0.2604→0.2623、4角は0.269→0.274に増える。予想移動の大きさは実際の約8割で、大きなまくり（例：18→2番手）は小さく出る。
- パラメーターは2025年6〜8月で選ぶ（1〜5月の学習モデルを使用。全頭そろう過去データは2026-11-18の取り込み直し以降は2023年から、それまでは実質2025年から）。検証の9〜12月は選定に使わない。採用値は `models/pace/report.json` の `contention`、選んだ設定の指標別の誤差比（独立予測比）は `contentionTuning`。
  既知の問題（2026-11-17確認）：v1.5で2角の馬身差 g2 が 3.69→3.92 に悪化し、独立予測（3.90）より悪くなった。再チューニングで変わった front（0.25→0.45）を同じデータで0.25に戻しても g2 は 3.817→3.826 と戻らず、他の指標も0.003以内で変わらないため0.45のまま（`scripts/experiment_contention_front.py`）。v1.6（2026-11-18）は現在のDB（行数17041→19006）で同じ手順のまま再チューニングし、frontは0.25が選ばれた（目的関数の差0.0002）。v1.5比の検証誤差は g2 3.92→3.83・l2・上がりが改善、g1 +0.01・l3 +0.011・r1/r2 +0.002 が悪化（DB更新の影響を含む）。目的関数は2角の内外（誤差比0.83）と上がり（0.95）の改善が大きく、馬身差（1.00〜1.02）の悪化を許す形で選ばれる。
- 検証（9〜12月273レース、平均絶対誤差。ポジション争いあり／なし／過去5走平均）：上がり 0.950／0.958／1.227秒。内外は2〜4角で改善（4角 0.553／0.559／0.619）、1角は悪化。馬身差はほぼ同等、順位は道中の位置変化を入れた分だけ3〜4角でやや悪化。
  公開する順位は整数の並びなので、過去平均（連続値）より誤差が大きい（4角 0.274 対 0.243）。数値は画面の「モデル・データの根拠」にも表示。
  同じ整数化をした過去平均と比べると負けていない（2026-11-17、同一データ・検証273レース。独立／ポジション争いあり／過去平均の整数化：1角 0.236/0.236/0.236、2角 0.241/0.242/0.244、3角 0.251/0.252/0.252、4角 0.260/0.262/0.262）。過去平均（連続値）との差は整数化そのものの損で、ポジション争いの害ではない。

`public/data/pace_forecasts.json`（形式 `paddock.pace-forecast/v1`、**版 1.1**）がアプリの取り込み口。

  "revision": "1.1",                           // 任意：形式の版（省略時は1.0）
  "generatedAt": "2026-11-08T12:00:00",
  "model": {"name": "モデル名", "metrics": {}, "notes": []},   // name のみ必須

            {"corner": 3, "rank": 2, "gap": 0.8, "lane": 1.0},  // 番手, 先頭からの馬身, 内からの位置

## 予想の不確実性の表示（追加指示4 フェーズ3、2026-11-18）
精度の頭打ちを前提に、「どこまで読めているか」を画面に出す。
- **モデル**（`scripts/pace_model.py` の intervals ブロック、版1.6）：各角の順位と上がり3Fに、分位点回帰（LightGBM `quantile`、α=0.25/0.75）を本モデルと並行に学習する。順位は FEATURES、上がりは LAST3_FEATURES（予想時はポジション争いの渋滞・消耗を入れる。quantile 目的は単調制約を使えないため制約なし）。
- **表示する値**：順位は番手（1＋q×(頭数−1) を四捨五入）、上がりは0.1秒に丸め、どちらも公開値（rank / last3）を含むよう広げる。被覆率はこの表示値で測る。
- **補正**：分位点の木は期間外で幅が狭すぎる（6〜8月で上がり3Fの25〜75%帯に入る実績は30%）。各側の幅を、6〜8月（6月より前で学習）で表示上の被覆率が50%に最も近くなるよう補正する（時系列分割の conformal 補正）。選んだ補正：順位 −0.030/−0.045/−0.055/−0.045（正規化順位）、上がり +0.26秒（整数化と公開値を含める拡張で順位は広がりすぎるため、順位は少し狭める）。
- **検証（9〜12月273レース、50%区間）**：被覆率 1角53%・2角50%・3角49%・4角50%・上がり54%、平均の幅は順位で約4番手、上がりで約1.5秒。補正なしでは順位57〜58%・上がり37%だった。被覆率が40〜60%を外れる項目は出さない（現状はすべて表示）。数値は `models/pace/report.json` の `intervals` と画面の「モデル・データの根拠」。
- **画面**：馬を選ぶと、詳細パネルに「予想レンジ（50%区間）」として最終角（通常は4角）の位置のレンジと上がり3Fのレンジを表示し、各角のカードにもレンジを小さく出す。実績再生では出さない。3D側の半透明バンド表示（任意）は未実装。
- 受け入れ：`npx tsc --noEmit`、`node scripts/check_*.mjs` 全件、14レース分の `pace_forecasts.json` を再生成して表示を確認（`check_pace.mjs` はレンジが頭数内・公開値を含む・被覆率を通った項目だけにあることも検査）。
