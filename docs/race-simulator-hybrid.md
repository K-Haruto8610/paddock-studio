# v3 と v2.0 の混成モデル：設計ノート（2026-11-23）

S4（`docs/race-simulator-s4.md`）の報告期間の結果で、勝ち負けが出力の種類に分かれた。勝った部分（角の順位・上がり・着順）は v3、負けた部分のうちペースは v2.0 の前半3F専用モデル、馬身差は v3 の形に広がり（spread）を外から補う形にした混成形を作り、同じ判定にかける。§1〜§5 は実装の前に固定した設計で、§6 以降が実測。

**最終結論（§9・§10）：不合格。公開予想は v2.0 のまま。** オーナー判断で着差を v3 のゴールタイム差 × 倍率に改め、選定期間で C2 を確定してから報告期間（273レース）を評価した。3・4角の馬身差と着差は両シードで v2.0 を上回ったが、1・2角の馬身差が両シードで下回った（+0.12 / +0.04、+0.07 / +0.03 馬身）。

**最初の判定（§1〜§6、着差を既存の恒等式で計算し直す形）：不合格（設計の関門で止まった）。** 馬身差の広がりの補正そのものは選定期間で効いた（C1・C2 は両シードで1〜4角の馬身差と着差で v2.0 を上回る）。しかし §4 の3条件を満たす候補が1つもない。既存の恒等式（着差 = 最終角の馬身差 + 5 × 上がりの差）で着差を計算し直すと、v3 の固定着順と矛盾するレースが、どの候補でも231レース中172〜212ある。しかも v3 の形を保ったレース単位の倍率では、どう選んでも矛盾が消えないレースが79 / 75（シード42 / 7）あり、形の保持をやめても、どんな単調な4角の馬身差でも整合できないレースがシード7に4つある。指示どおり、着順の並べ替えや着差の丸めで整合させず、報告期間（273レース）は評価していない。`public/data`・`models/`・v2.0 の生成経路には触っていない。

## 4. 着差の恒等式（既存実装に合わせる）

既存の実装は2か所あり、どちらも同じ式：v2.0 の `pace_model.race_output`（`scripts/pace_model.py` 1349〜1356行）と、`finish` が無いときのアプリの再生（`app/playback.ts` 87〜92行）。

```
着差_i = 最終角の馬身差_i + 5 × (上がり_i − min_j 上がり_j) − min_k [ 最終角の馬身差_k + 5 × (上がり_k − min_j 上がり_j) ]
```

- 単位は馬身、1秒 = 5馬身（`LENGTHS_PER_SECOND`）。差の向きはどれも「後ろが正」（0 以上）
- 基準馬：最終角の馬身差はその角の先頭（0）、上がりの差は一番速い上がりの馬、着差は和が最小の馬（勝ち馬、0）
- 最終角 = 公開する角のうち最後のもの（`positions` の最後、角のあるコースでは4角）
- 着差 MAE は E0 と同じく秒で採点する（着差 / 5 と実際の勝ち馬からの秒差の MAE）
- 参考：S4 の公開形は着差を v3 のゴールタイム差 × 5 で出していて、この式は満たしていない。v3 の走りの中で厳密に成り立つのは「ゴール = 残り600m地点 + 上がり」で、最終角の時刻は残り600m地点と一致しない

**検査する3条件（候補ごと・レースごと）。** 判定は丸める前の値で行う（数値誤差の許容 1e-9 馬身。丸めでは整合させない）。

1. 各角の馬身差が、v3 の角の順位に対して単調（順位が後ろの馬ほど馬身差が小さくない）
2. 着差が上の恒等式どおり（補正後の最終角の馬身差と v3 の上がりから計算した値と一致）
3. 計算し直した着差が、v3 の固定着順に対して単調（着順が後ろの馬ほど着差が小さくない）

候補ごとに違反レース数を記録し、3条件を同時に満たす（選定期間の両シードで違反0）候補だけを選定対象にする。満たす候補がなければ、固定着順の並べ替えや着差の丸めで整合させず、不合格として報告する。

## 5. 馬身差の継ぎ目：spread 候補と選び方

v3 の順序と相対的な形を保ち、角ごとにレース単位の広がりだけを補う。v2.0 と同じく「広がり」は角 c の先頭から80%位置の馬の馬身（`pace_model.SPREAD_Q = 0.8`）。

| 候補 | 角 c の馬身差 | 広がりの出所 |
|---|---|---|
| C0 無補正（S4） | 5 × (ct_i − ct_先頭) | なし |
| C1 v2.0 の spread モデル | S_c × (ct_i − ct_先頭) / (ct_80% − ct_先頭) | v2.0 の `spread<c>` の予測（`pace_model.prepare_race`） |
| C2 簡易 spread | 同上 | 頭数・距離・芝ダ・場（コース）・ペース（v2.0 の予測）からの中央値の線形回帰（角ごと） |
| C3 角ごとの定数倍 | k_c × 5 × (ct_i − ct_先頭) | ×5 換算前の時刻差を角ごとに k_c 倍（k_c は馬身差の MAE を最小にする値） |

- 比較：選定期間の同じ 231 レース・同じ角（v2.0 が採点する角で全頭にラベルのある角）・同じ MAE 集計（E0 の `g<c>`、全行の平均）。C0 と v2.0 も同じ表に載せる
- 選び方（固定）：まず §4 の3条件で絞る。残った候補の中で、選定期間の両シードで1〜4角の馬身差 MAE の平均が最小のもの。着差は恒等式から決まるので、選定では見るが選定基準には入れない
- 候補・係数・較正方法・合否基準を確定してから報告期間（273レース）を評価し、その結果を見て選び直さない

候補の作り方に依らない上限も測った：

- **v3 の形を保ったレース単位の倍率では直せないレース：79 / 75。** 4角の馬身差を v3 の時刻差の s 倍にすると、(3) を満たす s の範囲がレースごとに決まる（着順が前の馬 a と後ろの馬 b の組ごとに s の下限か上限が1つ）。この範囲が空のレースが 79 / 75 ある。補正の量（どの spread 予測を使うか）を変えても、ここは必ず違反する
- **どんな単調な4角の馬身差でも直せないレース：0 / 4。** 形の保持をやめて4角の馬身差を自由に（順位に単調に）選んでも、シード7の4レースでは v3 の4角の順位・上がり・着順の組み合わせが恒等式と両立しない（例：4角で a が b の前、ゴールで b が a の前、なのに b の上がりが a より遅い）

- 参考：実際の結果でも、実測の4角の馬身・上がり・確定着順を恒等式でつなぐと、235レース中221で着順と矛盾する（通過順の馬身は粗く、上がりは残り600mから）

**選定の結果：** §5 の決まり（3条件を選定期間の両シードで違反0）を満たす候補はない。§4 の指示どおり、固定着順の並べ替えや着差の丸めで整合させず、**不合格**とする。報告期間の評価・範囲の較正し直し・公開切替の作業には進まない（`hybrid.py` に予想生成の経路は作っていない）。

**記録しておく事実（判定には使わない）。**

- 着差の広がりも v3 は詰まっている：80%位置の馬の勝ち馬からの秒差の中央値は、実際 1.40 秒、v2.0 0.79 秒、v3 0.62 秒
- v3 自身の時刻の恒等式（着差 = ゴールタイム差。4角の馬身差とは結ばない）を使うなら、3条件のうち (1)・(3) は形の保持のままで必ず満たせる。そのうえでゴールタイム差を C3 と同じ作り方の倍率（1.80 / 1.82）で広げると、選定期間の着差は 0.635 / 0.620 秒（v2.0 との差 −0.061 / −0.073）。ただしこれは §4 の「既存実装の恒等式」ではない（S4 の公開形と同じく (2) に 223 / 223 レースで違反する）ので、候補に入れていない。恒等式の定義を変えるかどうかはオーナーの判断

## 7. 範囲表示への影響

補正が影響する表示項目を特定した：**なし**。

- `rankRange`：入力は v3 の角の順位（点の予想、変えない）と32回の乱数ありの走りの分位（変えない）。補正は馬身差だけを変え、順位を変えない
- `last3Range`：入力は v3 の上がりと32回の走り。どちらも変えない
- 馬身差・着差・ペースには公開する範囲がない（`pace.bands` は H/M/S の区切りで範囲ではない）

したがって混成形でも範囲は S4 と同じ入力から同じ値になり、較正し直す項目はない（S4 の係数を影響のある項目に流用するのではなく、影響のある項目が存在しない）。合格していれば、混成形の範囲が S4 の範囲と各馬で一致することを照合する予定だった。不合格のため、報告期間の被覆率の記録は S4 のノートに残す分だけになる（両シードとも記録済み、§10）。

## 8. 報告期間について

今回の報告期間は S4 と同じ期間（2025年9〜12月、273レース）での再比較で、設計の方針（v3 の順位・上がり・着順を残し、ペースは v2.0、馬身差は広がりを補う）そのものがその273レースの結果から生まれている。確認できるのは既知の弱点への同じ期間での改善幅で、新しい期間への汎化ではない。

最初の判定（§6）では設計の関門で止まったため、報告期間を評価していない。着差の定義を改めたあと（§9）、選定期間で候補を確定してから報告期間を一度だけ評価した（§10）。273レースの結果は設計にも選定にも使っていない。

予想の中身は `hybrid.race_forecast` の1本の経路で作り、評価もこの関数の出力を採点した。不合格なので、公開形式（`paddock.pace-forecast/v1`）へ書き出す部分と公開用モデル（`--window pub`）は作っていない。

海外馬はオーナー決定でモデルの対象外（外れを欠陥として数えない）。S3 で締めた問い（乱数ありの学習の損失変更、競り合いの固定、medoid の読み出し）は開き直さない。
