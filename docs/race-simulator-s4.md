# v3 S4：分離形を公開形に組んだ最終判定（2026-11-23、ブランチ exp/v3-s4-perrun）

**結論：不合格。公開予想は v2.0 のまま。** v3（S4）は報告期間（2025年9〜12月、273レース）で、角の順位（τ・整数MAE、全4角）、上がり、着順 τ では両シードとも v2.0 を上回った。しかし角の馬身差（4角すべて）とペースで下回り、着差もほぼ同じだった。設計の合格条件（E0 の全指標で v2.0 を上回る）を満たさない。`public/data` と `models/` には触っていない。

追加指示12（天皇賞（秋）・エリザベス女王杯の再現検証）の結果はこの判定に入れていない。記録は `docs/retro-gi/report.md` の §7。

## 2. 予想生成経路（作業1）

`scripts/v3/s4.py` を1本の経路として作った。

```
python -I scripts/v3/s4.py runs      --window sel|rep|pub --seed 42|7   # 点の予想＋32回の走り
python -I scripts/v3/s4.py calibrate --seed 42|7                         # 範囲の幅（選定期間）
python -I scripts/v3/s4.py evaluate                                      # E0 の全指標と被覆率、判定
python -I scripts/v3/s4.py forecast  --window rep|pub --seed 42 [--out FILE]
```

- 出力は現行の公開形式 `paddock.pace-forecast/v1`（revision 1.1）。各角の `rank`・`gap`・`lane`・`rankRange`、`last3`・`last3Range`、`finish`、`pace`（`early`・`label`・`bands`・`frontRunners`）。v2.0 にだけある任意の項目（`wantRank`・`held`・`boxed`・`last3Free`・`kickDelay`・`paceCost`）は出さない。v3 には対応する量がない
- 過去の GI は v3 の走の表（`outputs/v3/runs.pkl`）から作る。出走前のレース（マイルCSなど）は `data/entries` の出馬表から行を足し、レーティングは前日までの状態（`rating_index`）から取る
- ペースの区分（H/M/S）は v2.0 と同じ作り方にした：v3 自身が過去の GI（学習期間内）を予想した値の3等分点で区切る
- 範囲は v1.6 の決まりどおり、報告期間の被覆率が40〜60%の項目だけ出す
- 動作確認：選定期間のモデルで公開18レース分を出力し（`outputs/v3/pace_forecasts_v3_sel.json`、公開ファイルではない）、アプリ自体の検査 `scripts/check_pace.mjs` を通した（`PACE_FILE=` でファイルを差し替えられるようにした）。スキーマ、出走馬の一致、3D 再生との一致、結果を見ていないこと、馬の重なりなし：全レースで合格
- 点の予想は、記録済みの S2_gwe の予想（`s2_all_gwe_<期間>_seed<シード>.pkl`）と一致する（最大差 3e-5 秒。GPU の非決定性）

## 4. 最終評価の手順（作業3）

- **報告期間の比較に使うモデル**：確立した手順（`experiment-discipline`、v2.0 の `models/pace/report.json` と同じ）どおり、2025-09-01 より前で学習したモデル（`s2_all_gwe_rep_seed42/7`、`s3_all_gwe_split_rep_seed42/7`）で9〜12月を予想して比べた。指示の「2025年末までで再学習した最終形」で9〜12月を採点すると、採点するレースを学習に含んでしまう。2025年末までの再学習（`--window pub`）は公開用のモデルで、v2.0 と同じく合格したときだけ作る。不合格なので作っていない
- **v2.0**：公開中の v2.0 の設定（2020〜2026フレーム、レーティングあり、公開中のポジション争いの値、確立した手順）を同じ273レースで計算し直した値（`scripts/v3/baseline_v20.py`）。報告期間の τ は 0.444 / 0.418 / 0.373 / 0.354、上がり 0.786 で、公開値（0.442 / 0.414 / 0.376 / 0.361、0.788）とほぼ同じ（レースの集合が少し違う）
- **指標（E0）**：角ごとの τ と整数MAE（正規化。番手での値も併記）、馬身差（通過順表記の馬身との MAE）、上がり3F の MAE、ペース（コース標準との秒差の MAE。参考に相関、H/M/S の的中、RPS）、着順（着順 τ・着差 MAE、勝ち馬の的中は参考）。角は v2.0 が採点する角で、全頭に順位・馬身差・内外のラベルがある角だけ（`pace_model.labelled` と同じ）。同じレース・同じ馬で対にして、レース単位のブートストラップ（2,000回）で95%区間を出した
- **v3 のペース**：先頭のスタートから600m地点の時刻 − コース標準（v2.0 と同じ、2025年6月より前の前半3F の中央値。`scripts/v3/pace_actual.py`）
- **合格の決め方**：主指標（角 τ ×4、整数MAE ×4、馬身差 ×4、上がり、ペース MAE、着順 τ、着差）のすべてで、報告期間の両シードとも v2.0 より良いこと

## 6. 判定と所見

**不合格。** 下回った主指標：1〜4角の馬身差、ペース MAE、着差（同等で上回らない）。両シードとも同じ。公開予想の生成は v2.0 のまま切り替えない。

なぜ下回ったか（記録のため）：

- **序盤の隊列が詰まりすぎる。** 80%位置の馬の先頭からの馬身（報告期間、シード42）：実際 8.2 / 8.0 / 5.7 / 4.9（1〜4角）、v2.0 8.1 / 7.6 / 5.2 / 4.4、v3 **1.7 / 1.9** / 3.2 / 3.2。v3 の乱数なしの走りは、競り合いで各馬を望む位置へ引き寄せるので、1・2角では時刻差がほとんど開かない。並び（τ）は合っていても、×5馬身/秒の換算では馬身が足りない。S3 で gap_scale を学習させたとき 10 前後まで伸びたのも同じ理由（詰まった秒差を引き伸ばす）
- **ペースを読めていない。** 先頭の600m地点の時刻は、200mの倍数の距離でも（選定期間・シード42）ラップ実測より平均 +0.48秒遅い。レース間の並びの相関も低い（報告期間 0.18〜0.19、選定期間 0.12。v2.0 は 0.42〜0.44）。H/M/S の確率（RPS）は気候値（どのレースも過去の割合を出す）より悪い。v2.0 には前半3F 専用のペースモデルがあるのに対し、v3 の先頭の時刻は先頭のラップ損失（重み0.5）から間接に出るだけ。区分（H/M/S）は v3 自身の GI 3等分点で区切るので、的中率は v2.0 と同じくらい（0.44）になる
- 着差は、上がりと着順の並びが良くなった分と、隊列が詰まった分が打ち消し合って同等

順位・上がり・着順の改善（3・4角 τ +0.05〜+0.07、着順 τ +0.07）は、S1 以来どの期間でも出ている v3 の強み。馬身差とペースを直さない限り、設計の合格条件（E0 の全指標）は満たせない。

## 7. 記入待ち（乱数ありの走りの学習が終わり次第）

報告期間の乱数ありの走りのモデル（`s3_all_gwe_split_rep_seed42/7`、hold・gap_scale だけの学習）が学習中。この学習は点の予想に関わらないので、§5・§6 の判定は変わらない。終わったら、報告期間の範囲の被覆率（§3）と、内外の参考表示の全頭0との比をここに書き足す。
