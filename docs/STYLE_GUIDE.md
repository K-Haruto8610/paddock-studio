# STYLE_GUIDE（3Dの形と質感の方向性、2026-11-19 オーナー決定）

Paddock Studio の3Dモデルと質感の共通仕様。Blender でのモデリング担当と、Three.js 側の組み込み担当の両方がこれに従う。

> **2026-11-19 オーナー追記: 騎手は作らない。** `docs/visual-improvement-brief.md` の決定事項7（2026-11-15）を維持する。
> 本文中の騎手の項目（納品するオブジェクトの「騎手」、進め方の最後の「騎手」）は適用しない。
> 進め方は 頭 → 胴体のシルエット → 脚 の3段階になる。

## 全体の方向性

- 馬は「高品質なぬいぐるみ／フェルト」の質感。芝は、フェルトのように柔らかいマットな緑の草を、**1本ずつ生やす**。
- それ以外（ダート、ラチ、スタンド、建物、空、樹木）はリアル調。
- 意図は「ぬいぐるみの馬が本物の競馬場にいる」ジオラマ感。質感は混ぜず、照明・影・色調補正は全要素で統一する。

## 共通の禁止事項

- ローポリに見える平らな面（flatShading、角張った輪郭）は禁止。形はすべて滑らかな曲面で（Blender はサブディビジョン、Three.js 側はスムーズ法線）。
- プラスチック的なツヤ、原色のベタ塗りも禁止。

## 素材ごとの指定

- **馬**：ベロア／フェルト調。粗さ0.9以上、Sheen で毛羽の光を表現。布目の細かいノイズをバンプに。縫い目をディテールとして入れる。逆光で輪郭がわずかに光る短い毛足の表現を入れること。色は実行時に付けるので、テクスチャではなくマテリアル領域の分離で渡す（毛色／たてがみ・尾／蹄／勝負服の身頃・袖・帽子）。Three.js 側は MeshPhysicalMaterial の sheen が受け口。
- **芝**：草は**1本ずつ生やす**（インスタンスの草）。草も下の面も、フェルトのようなマットで柔らかい緑にして、うっすら色むらと刈り縞を付ける。艶やベタ塗りの緑にしない。馬と同じ素材言語（マット、毛羽の薄い光沢）で揃える。
  （2026-11-19 のオーナー修正。最初の版は「草は1本ずつ生やさず、面で表す」だった。）
- **ダート**：リアルな砂。粒感のあるテクスチャ（アルベド／粗さ／法線のPBR）と粗さの変化、蹄跡の表現。
- **ラチ・柵**：塗装金属のリアル調。白の汚れや使用感を少し入れる。角には小さなベベル。
- **建物・スタンド**：写真テクスチャのPBR。角には小さなベベル（現実に完全な直角はない）。
- **空・照明**：リアルな空と太陽光。ACES トーンマッピング、環境光、柔らかい影。全要素で同じ照明と色調補正を使う。

## モデリングの規約（Blender → Three.js）

- アニメーションはパーツ単位の頂点変形が前提（`app/plushHorse.ts` が仕様の出所）。単一メッシュではなく、胴体・頭・首・脚4本（付け根にピボット）・たてがみ・尾・鞍とゼッケン・騎手を別オブジェクトで、名前を付けて納品する。
- 座標規約：前方向 +X、地面 y=0、脚の付け根の高さ 0.95、脚の x 位置は前 0.64／後 −0.82（詳細は `app/plushHorse.ts`）。実寸スケール（メートル）。
- 予算：18頭同時表示の WebGL なので、1頭あたりのポリゴン上限を部品ごとに決めてから作る。

## 検証の方法

- 質感と形の確認は `app/plush-preview` と `app/surface-preview` のプレビューページで、固定アングル（横・斜め前・真上）のスクリーンショットを並べて比べる。
- 参考画像（理想のぬいぐるみ馬の写真、フェルトのジオラマ、本物の競馬場の写真）を指示と一緒に渡す。数値よりも見た目合わせを優先する。
- 進め方は1部品ずつ：頭 → 胴体のシルエット → 脚 → 騎手の順に「Blender で作る → コード側が組み込みを書き換える → プレビューで確認」を回す。

## 付記: Blender のモデルをアプリで使う（2026-11-19）

流れ: `blender/horse.py` で Blender の中に作る → `blender/export.py` で `public/models/horse.glb` に書き出す → アプリが読み込む。

- 読み込み: `app/blenderHorse.ts` の `loadHorseModel()`。部品は名前で受け取る（`horse_body`、`horse_menko`、`horse_ear_L/R`、`horse_eye_L/R`、`horse_nostril_L/R`、`horse_bridle_*`）。材質は書き出さず、色・布・毛足はアプリ側で付ける。
- 使い方: `plush(horse, {model: ...})`。指定なしは、モデルが読み込み済みなら Blender 版、なければコード版。`'blender'` を明示して読み込み前に呼ぶと例外、`'code'` を明示すると常にコード版（頭絡の書き込みページがこれ）。
- **レース画面は Blender 版が既定（2026-11-19 オーナー決定。尾のドックだけコードのまま）。** `app/page.tsx` は `useHorseModelReady()` で読み込みを待ってから 3D を作り、`/visual-check` も `ensureHorseModel()` を待つ。1 つの場面の馬は、すべて同じ作り方になる。読み込みに失敗したときはコード版に戻り、コンソールにエラーを出す。
- 確認: `/plush-preview` の「Blender のモデル」チェック（既定でオン。`?model=code` でオフから始める）。コード版と並べた比較は `blender/previews/app-code-vs-blender.png`（上がコード、下が Blender。左が静止、右が走り）。
- 脚の振りと頭の上下は、従来どおりアプリが頂点の位置から計算する。
- 革ひもは、毛足の上に乗るよう、アプリ側で外へ持ち上げる（`_cover` が 1 の頭巾の上では持ち上げ量が小さい）。

## 付記: たてがみ・尾・ゼッケン（2026-11-19）

- **ゼッケン**（`blender/saddle.py`）: 布 `horse_saddle`（10×24）と、左右の番号面 `horse_saddle_print_L/R`（12×12、UV 0..1）。胴体（脚つき、首と頭なし）の上に、アプリの `clothPoint` と同じ線で掛ける。布は胴から 25 mm 浮かせてあり、アプリが毛足の長さに合わせて放射状に持ち上げる。番号と馬名の文字は、これまでどおりアプリが実行時に描く。
- **たてがみ・尾**（`blender/hair.py`）: 毛そのものは数万本の細い管で、揺れは頂点シェーダーで付けている。手で作るものではないので、Blender が持つのは**ガイドの毛**。`horse_mane_guides`（メンコなし、150 房）、`horse_mane_guides_menko`（メンコの上に掛かる版）、`horse_tail_spine`（尾の中心線、37 点）。点を動かす、房を足す・消すと、アプリがその周りに毛を生やす。ガイドは辺だけのメッシュで、点ごとに `_strand`（房の番号）を持つ。
- アプリ側は Blender 版の馬で、ゼッケン、たてがみ、尾もモデルのものを使う。毛の生やし方（1房あたり約 60 本、散らし方、揺れ）は従来のコードのまま。
- 三角形: ゼッケン 1,056（布 480、番号面 288×2）。合計（毛のガイドを除く）は 16,680。
- 確認画像: `blender/previews/app-code-vs-blender-full.png`（上がコード、下が Blender）、`blender-full-horse.png`、`blender-guides-saddle.png`（Blender の中の見え方。毛のガイドは細い管で表示）。

## 付記: 質感の仕上げ（2026-11-19）

STYLE_GUIDE の「素材ごとの指定」を、レース画面のコードに反映した。確認画像は `docs/style-check/`。

| 素材 | 反映したこと | 場所 |
|---|---|---|
| 馬 | 布の粗さを 0.92 に（ベロア・ミンキー）。革の艶を弱める（粗さ 0.66、クリアコート 0.06）。布目のバンプを強める。胴とメンコの中心線に縫い目（溝と糸の針目）。 | `app/plushHorse.ts`（`stitchSeam`、`FABRIC_LOOKS`） |
| 芝 | 草は1本ずつ生やす（従来のとおり）。草の下の面と周りの地面は、フェルトのマット面（粗さ 1、毛羽の薄い光沢、細かい繊維の法線）。色むらと刈り縞は強めた。 | `app/surfaceFinish.ts`（`feltMaterial`）、`app/raceGrass.ts`、`app/scenery.ts` |
| ダート | 粒感の法線（従来）に、パッチごとに変わる粗さのマップを追加。蹄の砂煙も PBR に。 | `app/surfaceFinish.ts`（`sandRoughnessMap`）、`app/dirtTrail.ts` |
| ラチ | 6 角だった管と支柱を滑らかな曲面に。支柱の上下に小さなベベル。塗装の汚れ・使用感の模様。 | `app/surfaceFinish.ts`（`railPaintMap`、`paintedMetal`、`postGeometry`） |
| スタンド・建物 | 箱の角にベベル（0.2 m）。コンクリートの PBR（法線、粗さ、汚れの模様）、UV はメートル基準。 | `app/surfaceFinish.ts`（`concreteMaterial`、`bevelBox`）、`app/raceLandscape.ts` |
| 空・照明 | 空に雲を追加。環境光を、スタジオの箱ではなく空そのものから作る。トーンマッピング（ACES）、柔らかい影は全要素で共通だった。 | `app/raceLandscape.ts`（`skyDome`、`skyEnvironment`） |

**まだ満たしていない点**
- 建物とスタンドは「写真テクスチャの PBR」ではなく、手続きで作ったコンクリートの質感。写真の素材（アルベド・粗さ・法線）をもらえれば `concreteMaterial` に差し替える。
- 樹木は、丸めた塊のまま（リアル調ではない）。
- 逆光の輪郭光は、既存の毛足とシーン光源に任せていて、専用の調整はしていない。
- 縫い目は中心線だけ。脚の付け根や口まわりの縫い目は入れていない。
- 空は雲付きのグラデーションで、大気散乱の物理モデルではない。
