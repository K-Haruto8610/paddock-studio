# STYLE_GUIDE（3Dの形と質感の方向性、2026-11-19 オーナー決定）

Paddock Studio の3Dモデルと質感の共通仕様。Blender でのモデリング担当と、Three.js 側の組み込み担当の両方がこれに従う。

> **2026-11-19 オーナー追記: 騎手は作らない。** `docs/visual-improvement-brief.md` の決定事項7（2026-11-15）を維持する。
> 本文中の騎手の項目（納品するオブジェクトの「騎手」、進め方の最後の「騎手」）は適用しない。
> 進め方は 頭 → 胴体のシルエット → 脚 の3段階になる。

## 全体の方向性

- 馬と芝生は「高品質なぬいぐるみ／フェルト」の質感。
- それ以外（ダート、ラチ、スタンド、建物、空、樹木）はリアル調。
- 意図は「ぬいぐるみの馬が本物の競馬場にいる」ジオラマ感。質感は混ぜず、照明・影・色調補正は全要素で統一する。

## 共通の禁止事項

- ローポリに見える平らな面（flatShading、角張った輪郭）は禁止。形はすべて滑らかな曲面で（Blender はサブディビジョン、Three.js 側はスムーズ法線）。
- プラスチック的なツヤ、原色のベタ塗りも禁止。

## 素材ごとの指定

- **馬**：ベロア／フェルト調。粗さ0.9以上、Sheen で毛羽の光を表現。布目の細かいノイズをバンプに。縫い目をディテールとして入れる。逆光で輪郭がわずかに光る短い毛足の表現を入れること。色は実行時に付けるので、テクスチャではなくマテリアル領域の分離で渡す（毛色／たてがみ・尾／蹄／勝負服の身頃・袖・帽子）。Three.js 側は MeshPhysicalMaterial の sheen が受け口。
- **芝**：フェルトのマット調。草は1本ずつ生やさず、柔らかい緑の面にうっすら色むらと刈り縞。馬と同じ素材言語で揃える。
- **ダート**：リアルな砂。粒感のあるテクスチャ（アルベド／粗さ／法線のPBR）と粗さの変化、蹄跡の表現。
- **ラチ・柵**：塗装金属のリアル調。白の汚れや使用感を少し入れる。角には小さなベベル。
- **建物・スタンド**：写真テクスチャのPBR。角には小さなベベル（現実に完全な直角はない）。
- **空・照明**：リアルな空と太陽光。ACES トーンマッピング、環境光、柔らかい影。全要素で同じ照明と色調補正を使う。

## モデリングの規約（Blender → Three.js）

- アニメーションはパーツ単位の頂点変形が前提（`app/plushHorse.ts` が仕様の出所）。単一メッシュではなく、胴体・頭・首・脚4本（付け根にピボット）・たてがみ・尾・鞍とゼッケン・騎手を別オブジェクトで、名前を付けて納品する。
- 座標規約：前方向 +X、地面 y=0、脚の付け根の高さ 0.95、脚の x 位置は前 0.64／後 −0.82（詳細は `app/plushHorse.ts`）。実寸スケール（メートル）。
- 予算：18頭同時表示の WebGL なので、1頭あたりのポリゴン上限を部品ごとに決めてから作る。

## 検証の方法

- 質感と形の確認は `app/plush-preview` と `app/surface-preview` のプレビューページで、固定アングル（横・斜め前・真上）のスクリーンショットを並べて比べる。
- 参考画像（理想のぬいぐるみ馬の写真、フェルトのジオラマ、本物の競馬場の写真）を指示と一緒に渡す。数値よりも見た目合わせを優先する。
- 進め方は1部品ずつ：頭 → 胴体のシルエット → 脚 → 騎手の順に「Blender で作る → コード側が組み込みを書き換える → プレビューで確認」を回す。

## 付記: 2026-11-19 時点の現行コードとの差（組み込み担当向けメモ）

オーナー決定の本文ではなく、着手前の現状確認。行番号は 2026-11-19 時点。

**既存の指示書（`docs/visual-improvement-brief.md`）との食い違い。2026-11-19 にオーナーが決定:**

1. 写実: 指示書の「写実に寄せない」は本ガイドで置き換える（馬と芝はぬいぐるみ、それ以外はリアル調）。指示書の該当行も書き換えた。
2. 騎手: 指示書の決定事項7「騎手のぬいぐるみは作らない」を維持する。本ガイドの騎手の項目は適用しない（冒頭の追記）。

**本ガイドどおりに直す必要がある点:**

- 芝は現在、1本ずつの草を立てている（`app/raceGrass.ts` は 130本/m²、`app/surfaceDetail.ts` の blade と shell）。本ガイドは「草は1本ずつ生やさず」。

- 馬は Blender のデータを読み込む経路がまだない。現在は `app/plushHorse.ts` がコードで形を作っている（MarchingCubes 等）。glTF の読み込み（`GLTFLoader`）から入れる必要がある。
- 馬の布の設定（`app/plushHorse.ts:353` 付近の `FABRIC_LOOKS`）は、velour が粗さ 0.7、minky が 0.85 で、「粗さ0.9以上」を下回る。採用中の胴の布（`SAVED_FABRIC.body`）は velour。leather は clearcoat 0.3。
- ラチの支柱は 6 角の円柱（`app/sceneBuilders.ts:205`）で、近くでは角張って見える。素材は `MeshStandardMaterial` の単色（汚れ・ベベルなし）。
- スタンドは素の箱（`app/raceLandscape.ts:77` 付近）。写真テクスチャもベベルもない。
- ダートは `MeshLambertMaterial` の単色（`app/dirtTrail.ts:191`）。PBR のテクスチャはない。
- 空はシェーダーの球（`app/raceLandscape.ts:6` `addRaceSky`）。

**すでに合っている点:**

- ACES トーンマッピングは本番（`app/sceneQuality.ts`）と3つのプレビューページで共通。
- 馬の布は `MeshPhysicalMaterial` の sheen を使っている。
- 脚の付け根 0.95、x 位置 前 0.64／後 −0.82 は `app/plushHorse.ts:49-54` と一致。

## 付記: ポリゴン予算（2026-11-19）

頭だけの予算 10,000 三角形（承認済み）は、頭と胴体を一体の殻にしたため、次の内訳に置き換える。
**アプリは元々、胴・首・頭を一枚の縫い目のない布の殻にしていた（`bodyDistance`）。Blender の `horse_body` も同じく一体。**
**脚も同じ殻に含める（2026-11-19 オーナー決定。モデリングの規約の「脚4本を別オブジェクトで」は適用しない）。** 脚の振りは、アプリが頂点の位置から計算する（`legRig`）。たてがみ、尾、ゼッケンは別部品で、予算はそれぞれの着手時に決める。
