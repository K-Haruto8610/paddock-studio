# 展開予想 v3 設計：競馬の仕組みを持つ学習型レースシミュレーター

2026-11-22 草案。v2.0（LightGBM＋手書きの隊列規則）を置き換える候補の設計。

## 1. なぜ作り直すか

v2.0 は1頭ずつ独立した回帰を13本（各角の順位・馬身差・内外×4角＋上がり）並べ、手書きの規則（並走、控える、横4頭）で隊列に組み、着順は「4角の馬身差＋上がり差×5」で後から合成している。位置・馬身差・上がり・着順が1つの走りから出ておらず、互いの整合はたまたまでしかない。

v2.0 自身の検証（`models/pace/report.json`、9〜12月）でも、規則の層は順位と馬身差を悪くしている。

| | 公開（規則あり） | 独立予想 | 参考 |
|---|---|---|---|
| 順位 MAE r3 / r4 | 0.239 / 0.247 | 0.236 / 0.242 | 過去走平均 0.227 / 0.233 |
| 馬身差 MAE g1 / g4 | 3.31 / 2.18 | 3.26 / 2.14 | 馬ごと直接 3.07 / 2.04 |
| 上がり MAE | 0.784 | 0.890 | 過去走平均 1.168 |

v3 の目標は「競馬という競技の仕組みをモデルの構造として持ち、その仕組みの強さをデータから学ぶ」こと。手法は目標から選ぶ。LightGBM は決まった正解を当てる学習しかできず、シミュレーターを通して学習できないので使わない。

## 2. 基本の考え方：レースを距離と時間の上で走らせる

隊列・馬身差・上がり・着順は、どれも「各馬がコース上の各地点を何秒で通過したか」の別表現である。

- 角の順位＝その地点の通過タイムの並び
- 馬身差＝通過タイム差 × 約5馬身/秒（区切り記号の実測幅は `jv-per-horse-600m-time` の測定を使う）
- 上がり3F＝ゴールタイム − 600m地点タイム
- 着順・着差＝ゴールタイムの並びと差

そこで v3 は、各馬の速度をスタートからゴールまで刻みで進めるシミュレーターを中心に置く。出力はすべてこの1回の走りから読み出すので、作りの上で矛盾しない。3D再生（replays.json）も角の補間ではなく、走りの軌跡をそのまま使える。

## 4. データで確かめた競馬の仕組み

`scripts/measure_race_mechanics.py`（キャッシュ済みフレーム、6,000レース・80,553頭）で測った。シミュレーターの各項の根拠と、学習後に再現できているかの確認に使う。

| # | 仕組み | 測った値 | 設計への意味 |
|---|---|---|---|
| M1 | 勝負は最後の600m | 着差との相関：600m地点の差 0.18、上がり 0.79 | 末脚と仕掛けのモデル化が最優先 |
| M2 | ペースが速いと前が止まる | 前1/3と後1/3の上がり差：最速の5分の1で0.72秒、最遅で0.20秒。ペース1秒あたり0.22秒 | 速度とスタミナの消耗を物理的な項で持つ（M2の傾きは学習後の確認項目） |
| M3 | 外を回るロス | 隊列記号の「並走の何番目」は、同じ馬の中で比べても上がりにほぼ効かない（1列あたり−0.01秒） | 記号の内外はコース上の実際の外目と別物。距離ロスはデータからは学べないので、コース形状から幾何で計算する |
| M4 | 前半と後半の速度 | 芝1400m超は後半が速い（1.03〜1.05倍）、ダートは後半が遅い（0.96〜0.99倍） | 芝とダートで消耗の仕方を分ける |
| M5 | 枠と位置取り | 同じ馬の中で比べると、枠の影響は1角の位置に±0.02しかない | 位置取りは主に馬の脚質（意思と二の足）で決まる |
| M6 | 脚質の持続 | 1角の位置と過去走の相関 0.55、上がりと過去走 0.60 | 馬ごとの潜在能力を過去走から推定する部分が要る |

## 5. モデルの構成

### 5.1 馬の能力（潜在ベクトル）

各馬を少数の解釈できる能力値で表す。

- 巡航速度：無理なく保てる速度（臨界速度）
- スタミナ：臨界速度を超えて使える余力（無酸素の貯え）
- 最高速：末脚の天井
- ダッシュ：スタート直後の加速
- 位置取りの意思：前に行きたいか、控えたいか
- 仕掛けの早さ：最後の追い出しをどこから始めるか

これらは**過去走の列から推定する**。各過去走（コース、距離、馬場、そのレースの観測：600m地点の差、上がり、ラップ）を入力にした小さな系列エンコーダーで作り、シミュレーターと一緒に学習する。斤量・年齢・馬場・距離への適性は、この能力値への補正として入れる。過去走がない馬は、条件（年齢、クラス、距離）から作った事前分布から始める。

### 5.2 シミュレーター

刻み（例：10m）ごとに、各馬の状態を進める。

- 状態：走った距離、コース上の横位置（内ラチからのm）、速度、残りスタミナ
- 速度の選び方：意思（行きたい位置）と仕掛けのタイミングから目標速度を決め、最高速とスタミナで上限をかける
- スタミナ：臨界速度を超えて走った分だけ減り、尽きると速度が落ちる（運動生理学の臨界速度モデル）。M2 のペースと消耗の関係はここから自然に出るはず
- コーナー：横位置が外ほど走る距離が延びる（半径＋横位置）。M3 によりデータからは学べないので、コース形状から幾何で決める
- 前が詰まる：同じ横位置で前の馬に1馬身以内まで迫ると、その馬の速度に抑えられる。抜くには外へ出る必要があり、外へ出る分は距離と時間のロスになる
- 風よけ（任意）：前に馬がいると消耗が少し減る。効くかどうかは学習に任せる
- スタート：ゲート番号から最初の横位置、ダッシュから最初の加速

### 5.3 学習

- シミュレーター全体を、誤差を逆に流せる形（PyTorch）で書く。詰まりや並び替えのような飛びのある処理は、学習中は滑らかな近似（シグモイド）に置き換え、公開時は元の規則で走らせる
- 確率的に走らせる：各馬のその日の出来、スタートの出遅れを乱数で入れ、1レースを複数回走らせて分布を作る
- 損失（実際の記録との差）：
  - 先頭の200mラップ（全距離）
  - 各馬の600m地点タイム、ゴールタイム、上がり
  - 各角の通過順（シミュレーターの通過タイムを使ったペアごとの並びの尤度）
  - 隊列記号の馬身差（記号の幅の実測とその誤差を考慮）
- 学習するのは、能力のエンコーダーと、仕組みの強さ（消耗率、詰まりのロス、風よけ、仕掛けの規則）。仕組みの形そのものは固定する

### 5.4 出力

今の `paddock.pace-forecast/v1` をそのまま満たす。

- 角ごとの順位・馬身差・内外
- 上がり、着順・着差
- 範囲：複数回の走りから作った分位

これに加えて、走りの軌跡（距離ごとの位置）も出力し、3D再生に使う。

## 6. 評価：「競馬を理解しているか」をどう確かめるか

1. 当たるか：E0 の手順で、同じフレーム・同じ273レース・シード42/7のまま v2.0 と比べる（`experiment-discipline` の採用基準）。比べる値は、隊列の τ、整数順位 MAE、馬身差、上がり、着順
2. 矛盾しないか：馬身差・上がり・着差が同じタイムから出ていることを、全出力で検算する（作りの上で0になるはず）
3. 仕組みを再現するか：学習で直接教えていない関係が出てくるかを見る
   - M2：ペース1秒あたり前後の上がり差が約0.22秒
   - M4：芝の後半加速とダートの後半失速
   - 距離が延びるほど逃げ馬の残り方が変わる
4. 反実仮想が筋が通るか：
   - 同じ馬を速いペースの組に入れると上がりが遅くなる
   - 外を回らせると、幾何どおりの時間を失う
   - 逃げ馬を除くとペースが緩む

## 7. 段階計画

段階ごとに別ブランチで進め、前の段階（最初は v2.0）に勝ったものだけを main に入れる。

| 段階 | 中身 | 合格の目安 |
|---|---|---|
| S0 準備 | PyTorch（Python 3.14 用 2.15.0 あり）の導入。10場すべてのコース表（コーナーの開始・終了地点、半径、直線の長さ）。今は5場だけ | 全学習レースでコースが引ける |
| S1 単独走 | 相互作用なし。各馬が自分の能力だけで走り、ラップ・600m地点・ゴールに合わせる | 上がりと着順で v2.0 と同等以上。順位は v2.0 に負けてもよい |
| S2 ペースの相互作用 | 位置の取り合い、先頭が決まる仕組み、ペースによる消耗 | 順位の τ で v2.0 を上回る。M2 を再現する |
| S3 横位置と詰まり | 横位置、コーナーの距離ロス、詰まり、外へ出す | 馬身差と内外で v2.0 以上 |
| S4 確率化と公開 | 複数回の走り、範囲、出力形式、3D再生 | E0 の全指標で v2.0 を上回り、採用 |

## 8. リスク

- データ量：6,115レース。能力値を少数に絞り、仕組みの形を固定することで補う
- 横方向は観測が弱い（M3）。幾何で決め、学習させない
- 滑らかな近似と公開時の元の規則がずれる。公開時の規則で検証する
- 学習が局所解に落ちる。S1 の単独走から順に積み上げて初期値を作る
- 計算時間：1レース×複数回×刻み。GPU なしで学習が回るか、S1 で測る

## 9. 決めてほしいこと

- 名前付きでない一般レース（約3.7倍の行）を学習に入れるか。v2.0 では悪化したが、仕組みは共通なので、クラス差を能力の補正として持たせれば効く可能性がある
- 公開を段階ごとに切り替えるか、S4 まで v2.0 のままにするか
